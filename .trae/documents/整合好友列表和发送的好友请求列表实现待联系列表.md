# 实现计划

## 1. loadFriendRequests调用分析

| 位置 | 调用场景 | 作用 |

| 266行 | 检查到新好友请求 | 发现新请求时刷新列表 |

## 2. 实现方案

### 方案选择：新建loadPendingContactList方法
- **原因1**：loadFriendRequests已有明确职责（仅加载好友申请列表）
- **原因2**：待联系列表需要整合多种数据源，逻辑更复杂
- **原因3**：保持代码模块化，便于维护和扩展
- **原因4**：不影响现有功能的正常运行

### 3. 实现步骤

#### 步骤1：创建loadPendingContactList方法
```javascript
async loadPendingContactList() {
  // 1. 获取好友列表
  // 2. 获取好友申请列表
  // 3. 分离出"我发送的申请"
  // 4. 合并好友列表和发送的申请列表
  // 5. 统一数据格式
  // 6. 按时间倒序排序
  // 7. 设置到页面数据
}
```

#### 步骤2：整合数据源
- **好友列表**：通过`wx.$TUIKit.getFriendList()`获取
- **好友申请列表**：通过`wx.$TUIKit.getFriendApplicationList()`获取，筛选出"我发送的申请"

#### 步骤3：统一数据格式
确保每个条目包含：
```javascript
{
  id: userID,                  // 用户ID
  name: nickname,              // 用户名/昵称
  avatar: avatarUrl,           // 头像
  time: timestamp,             // 时间（最后联系时间/申请时间）
  type: 'friend' | 'applying', // 关系类型
  status: status               // 申请状态（如果是申请）
}
```

#### 步骤4：时间排序逻辑
```javascript
// 按时间倒序排序
const sortedList = combinedList.sort((a, b) => b.time - a.time);
```

#### 步骤5：调用时机
在以下场景调用新方法：
- 页面初始化（替换或补充原loadFriendRequests调用）
- 好友列表更新事件
- 好友申请状态变化事件
- 页面切换到待联系标签页时

#### 步骤6：更新事件监听
- 在`setImEventListeners`方法中添加好友列表更新监听
- 确保当好友列表或申请列表变化时，待联系列表同步更新

#### 步骤7：UI更新
- 添加新的页面数据字段`pendingContactList`
- 更新WXML模板，支持展示不同类型的联系人
- 处理空列表情况

## 5. 预期效果
- 用户可以在待联系列表中看到所有好友和自己发送的好友请求
